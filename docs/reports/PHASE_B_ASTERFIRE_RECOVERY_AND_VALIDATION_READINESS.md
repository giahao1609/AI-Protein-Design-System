## 4. RFab Root Cause Analysis and Implemented Fixes

### 4.1. Root Cause Identification
The 5 abandoned RFab nodes (targeting VHH tracks: EGFR, TNF-alpha, GLP-1R, TfR1, TNFR1) failed during initial framework acquisition:
1. **Unstable Framework URLs:** RFantibody scripts attempted to fetch framework PDBs (`h-NbBCII10.pdb`, `hu-4D5-8_Fv.pdb`) from remote URLs without connection timeouts or mirror redundancy.
2. **Silent HTTP Error Corruption:** Network intermediaries returning 404/503 HTML error payloads were written directly to disk as `.pdb` files, causing downstream gemmi/PyRosetta parsers to crash with cryptic syntax errors.
3. **Absence of Offline Fallback:** When internet access was restricted or DNS lookups failed in airgapped cluster worker nodes, the pipeline lacked a local template cache.

### 4.2. Implementation on Branch `fix/rfab-framework-url` (Commit `1e4ef36`)
We created an isolated remediation module in `src/protein_design/generators/rfab.py`:
- `CANONICAL_FRAMEWORK_REGISTRY`: Verified primary HTTPS URLs and jsDelivr CDN mirrors for standard nanobody and antibody frameworks.
- `validate_url()`: Enforces HTTPS, strips malformed characters, and validates host presence.
- `validate_pdb_content()`: Inspects the first 500 bytes for standard PDB keywords (`HEADER`, `ATOM`, `REMARK`, `CRYST1`) and rejects HTML/JSON error payloads.
- `_download_single_url()`: Implements exponential backoff retries with random jitter (configurable timeout and retry counts).
- `resolve_framework()`: First checks local cache (`data/frameworks/`), then tries primary and mirror URLs, and gracefully falls back to `MINIMAL_VHH_FRAMEWORK_PDB` in offline or test environments.
- `RFabGenerator`: Subclasses `BaseGenerator` and integrates resolved framework metadata into `Candidate` records.

## 5. Concurrency-Safe Execution Fallback Feasibility

### 5.1. AsterFire Capabilities vs Constraints
Telemetry and API analysis of AsterFire (`SAI-compute-NEW`) indicate:
- **Cluster Quota:** 1 active GPU slot per user account.
- **Batch Submission Hazard:** Submitting >1 task simultaneously returns:
  `RuntimeError: cluster_code=SAI-compute-NEW operation=submit_job: 并发任务数超出限制，请稍后重试`
- **Exhaustion Penalty:** 3 failed batch retries transitions nodes into `hold=infra`, halting automated pipeline progression.

### 5.2. Local Concurrency-Safe Scheduler (`src/protein_design/core/concurrency.py`)
To prevent future cluster deadlocks, we engineered `ConcurrencySafeScheduler`:
1. **Serialized Submission (`max_concurrency=1`):** Ensures exactly one job is dispatched to the worker at any given time.
2. **Dependency Resolution:** Traverses the workflow DAG and triggers child nodes only when all parents are `SUCCESS` or `SKIPPED_CACHED`.
3. **Queue Backpressure:** Blocks dispatching until active worker processes report completion.
4. **Exponential Backoff:** On transient cluster rejections, sleeps for `base_backoff * (2 ** retry_count)` before attempting re-submission.
5. **Resume Idempotency:** Queries `completed_artifacts` before execution; if a task's output artifact already exists and passes validation, it transitions immediately to `SKIPPED_CACHED` without consuming compute resources.

### 5.3. Verification
Verified via `tests/unit/test_concurrency_scheduler.py` (5 tests passing):
- Linear execution in strict dependency order.
- Maximum observed concurrent tasks strictly `<= 1`.
- Exponential backoff recovery after simulated transient cluster failures.
- Cascade halting when upstream nodes suffer unrecoverable failures.
- Idempotent resumption skipping pre-computed artifacts.

## 6. Scientific Scoring Provenance Audit

### 6.1. Audit Methodology
We audited the sequence, structure, and metric records of all 66 candidates across the 7 competition targets in `protein_design.db` and the filesystem.

### 6.2. Key Provenance Findings
1. **Nature of Current ipSAE Scores:**
   - The reported ipSAE scores (e.g. `0.5167` and `0.4939`) are **NOT computed from physical 3D co-folded structures predicted by neural networks**.
   - In `src/protein_design/predictors/esmfold_ipsae.py`, line 91:
     ```python
     seq_hash_int = int(hashlib.md5(candidate.sequence.encode()).hexdigest()[:8], 16)
     seed = candidate.seed or (seq_hash_int % 1000000)
     rng = random.Random(seed)
     ```
   - Scores are computed via a **deterministic heuristic proxy** (`compute_ipsae_score`) using pseudo-random variations around baseline estimates.
2. **Investigation of Repeated Maximum Scores:**
   - **Score `0.5167` (Repeated in TNF-alpha, TfR1, TNFR1):**
     In `src/protein_design/generators/vhh.py`, targets without specific amino acid weighting (TNF-alpha, TfR1, TNFR1) execute identical random sampling loops when initialized with the default seed `42`. Candidate 5 across all three tracks was assigned the exact same seed (`47`), resulting in bitwise identical sequences and bitwise identical proxy scores of `0.5167`.
   - **Score `0.4939` (Repeated in TL1A and IL-7Ra):**
     Both tracks used `BindCraftGenerator` operating on the static test fixture `tests/fixtures/bindcraft_output/final_design_stats.csv`. Candidate 1 in both tracks ingested the exact same mock metric record, yielding identical proxy scores of `0.4939`.
3. **Structure File Audit:**
   - File `candidates/GLP-1R/vhh_000001/structure.cif` contains 4 lines:
     ```cif
     # De novo VHH Scaffold structure for vhh_000001
     # Target: GLP-1R, Length: 109
     data_vhh_000001
     _entry.id vhh_000001
     ```
   - No atomic coordinates, no electron density, and no residue-level B-factors exist in local candidate structure files.

### 6.3. Scientific Demarcation
- **Software Quality Control vs Biological Validity:** Passing in silico developability gates (charge balance, pI, lack of deamidation motifs) verifies that sequences are synthetically plausible and developable. It does **NOT** prove thermodynamic stability or nanomolar affinity ($K_D$) in vitro.
- **Zero Hallucination Policy:** We explicitly state in all generated submission documentation that early-claim scores represent pipeline verification values, not experimental binding measurements.

## 7. Calibration Integration Readiness

### 7.1. Expected Schema of `thresholds.json`
The terminal node `threshold_compute` in AsterFire Execution 24000 outputs a JSON payload structured as follows:
```json
{
  "generated_at": "2026-11-06T12:00:00Z",
  "execution_id": "execution_24000",
  "tracks": {
    "EGFR": {
      "target_id": "EGFR",
      "track_id": 1,
      "baseline_true_ipsae": 0.824,
      "decoy_distribution": {
        "mean": 0.221,
        "std": 0.045,
        "p95": 0.285,
        "num_decoys": 20
      },
      "noise_floor_ipsae": 0.285,
      "calibrated_threshold": 0.554,
      "calibration_status": "CALIBRATED",
      "method": "mean_plus_2std"
    }
  }
}
```

### 7.2. Statistical Interpretation & Quality Gates
Implemented in `src/protein_design/validation/calibration.py`:
- **Signal-to-Noise Ratio (SNR):**
  $$\text{SNR} = \frac{\text{baseline\_true\_ipsae}}{\max(0.01, \text{noise\_floor\_ipsae})}$$
  A target calibration is marked reliable only if $\text{SNR} \ge 1.25$ and the separation margin $(\text{baseline} - \text{noise}) \ge 0.10$.
- **Decoy Distribution:** Encapsulates the mean and 95th percentile of 20 non-binding decoy sequences. If true complex ipSAE cannot be resolved from the decoy noise floor, the target is flagged as uncalibrated.
- **Production Guardrail:** Target YAML files (`competition/targets/*.yaml`) currently maintain `threshold: null`. No fabricated thresholds have been injected into production configs. Verified offline via `tests/unit/test_calibration.py`.
